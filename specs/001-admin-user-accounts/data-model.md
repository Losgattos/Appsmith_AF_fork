# Data Model: Администрирование — управление учётными записями

**Feature**: `001-admin-user-accounts` | **Date**: 2026-09-20

Сущности по спеке и фактической схеме БД (снапшот `Appsmith_DB` 17.09.2026, схема `appsmith`).

## 1. users (Учётная запись)

Таблица `appsmith.users` — фактическая схема:

| Поле | Тип | Ограничения | Комментарии |
| --- | --- | --- | --- |
| `id` | integer | PK, identity (GENERATED BY DEFAULT AS IDENTITY) | не редактируется |
| `directory_inn_id` | bigint | NOT NULL, FK → `directory_inn` | учреждение |
| `login` | text | nullable в БД; бизнес-правило: **уникален**, NOT NULL на уровне приложения (FR-011) | проверка без учёта регистра |
| `password` | text | nullable в БД; бизнес-правило: обязателен при создании (US2), 1–11 символов только латиница/цифры (FR-007) | хэширование отложено |
| `role_id` | integer | FK → `user_role` | роль |
| `is_user_enabled` | boolean | NOT NULL DEFAULT true | статус активности |

**Связи**: `users.directory_inn_id → directory_inn.directory_inn_id`; `users.role_id → user_role.role_id`; `users.id ← user_sessions.user_id`; `users.id ← name_report_2026.report_status_history.user_id`.

**Валидация (из спеки)**:
- логин: обязателен, уникален после trim (US2/AC2, FR-011);
- пароль при создании: обязателен, формат `[a-zA-Z0-9]{1,11}` (FR-007); при редактировании пустое поле = без изменений (FR-003);
- роль и учреждение: обязательны, из справочников (US2/AC4);
- удаление: запрещено при наличии сессий или истории отчётов (FR-004).

## 2. directory_inn (Учреждение, справочник)

Таблица `appsmith.directory_inn`. Поля для селекта формы/списка: `directory_inn_id` (PK), `inn`, `short_name` (label), `full_name`.

- Поле учреждения в форме: Select, options `get_directory_inn.data.map(o => ({label: o.short_name, value: o.directory_inn_id}))`.
- Отсутствующее значение (NULL-строка) отображается пустым; редактирование требует выбора (edge case).

## 3. user_role (Роль, справочник)

Таблица `appsmith.user_role`. Поля: `role_id` (PK), `print_name` (label), `system_name`. Опции селекта — из `get_user_roles.data` (`label: print_name, value: role_id`).

## 4. user_sessions (Сессия)

Таблица `appsmith.user_sessions`. Поля: `sessions_id` (PK), `user_id` (FK), `start_time`, `end_time`.

- Наличие любой записи (включая завершённые) = «пользователь входил» → запрет удаления (FR-004, edge case).
- Активная сессия: `end_time > now()` → гасится установкой `end_time = now()` при блокировке или смене пароля (FR-006, реализовано в `save_user`).

## 5. report_status_history (История отчётов)

Таблица `name_report_2026.report_status_history`. Поле `user_id` (FK). Наличие записей → запрет удаления (FR-004).

## Состояния учётной записи

```
[активна] --блокировка (is_user_enabled=false)--> [заблокирована]
[заблокирована] --разблокировка--> [активна]
[*] --удаление (нет сессий И нет истории)--> [удалена]
```

Блокировка и смена пароля в одном сохранении: сессии гасятся, если пользователь стал неактивен ИЛИ пароль изменён (edge case; в `save_user` условие `NOT is_user_enabled OR password <> ''`).
