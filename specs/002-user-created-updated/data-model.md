# Data Model: Даты учётных записей (создание/изменение)

**Feature**: `002-user-created-updated` | **Date**: 2026-09-23

## Entity: Учётная запись (appsmith.users)

Единственная изменяемая сущность фичи. Добавляются два атрибута:

| Поле | Тип | Null | Default | Примечание |
|------|-----|------|---------|------------|
| `created_at` | `timestamp without time zone` | NOT NULL | `(now() AT TIME ZONE 'Europe/Moscow')` | Устанавливается БД в момент INSERT; далее не изменяется (FR-005). **МСК-значение явно** (правка 23.09.2026, день). |
| `updated_at` | `timestamp without time zone` | NULL до первого изменения | — (без DEFAULT) | При INSERT остается **NULL** (заполняется только при реальном изменении); при любом UPDATE обновляется триггером (FR-004). Решение 23.09.2026 (вечер): «Изменено» пусто, пока запись не правили. Триггер пишет МСК явно (правка 23.09.2026, день). |

## Объекты БД (добавляемые)

### Функция `set_updated_at()`

```sql
CREATE OR REPLACE FUNCTION appsmith.set_updated_at() RETURNS trigger AS $$
BEGIN
    NEW.updated_at := (now() AT TIME ZONE 'Europe/Moscow');  -- МСК явно (правка 23.09.2026)
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

Общая функция (переиспользуема для будущих таблиц с датами, e.g. `directory_inn` в фиче «Управление учреждениями»).

### Триггер `trg_users_updated_at`

```sql
CREATE TRIGGER trg_users_updated_at
    BEFORE UPDATE ON appsmith.users
    FOR EACH ROW
    EXECUTE FUNCTION appsmith.set_updated_at();
```

Срабатывает на любом UPDATE строки `users` — включая правки мимо интерфейса (прямой SQL, будущие миграции). `created_at` триггер не трогает.

## Связи

- `users.directory_inn_id` → `directory_inn.directory_inn_id` — без изменений.
- `users.role_id` → `user_role.role_id` — без изменений.
- Новые поля не участвуют в связях; «дата изменения» не порождает новых сущностей и внешних ключей.

## Правила валидации (из спеки)

- `created_at` — всегда непустой (NOT NULL, FR-008 для даты создания).
- `updated_at` — **может быть NULL** до первого изменения записи (уточнение 23.09.2026 вечером к FR-008): «Изменено» заполняется только когда запись реально менялась.
- `created_at` не изменяется при правках (FR-005) — обеспечивается тем, что приложение и триггер его не пишут.
- `updated_at` обновляется при любом изменении записи (FR-004) — триггер BEFORE UPDATE.

## Миграция (единый скрипт, выполняется через psql)

Порядок критичен: **бэкфилл ДО создания триггера** (иначе триггер перезапишет `updated_at` значением now() во время бэкфилла).

```sql
-- 1. Колонки (существующие строки получат DEFAULT = момент миграции)
ALTER TABLE appsmith.users
    ADD COLUMN created_at timestamp without time zone NOT NULL DEFAULT now(),
    ADD COLUMN updated_at timestamp without time zone NOT NULL DEFAULT now();

-- 2. Бэкфилл существующих записей (решение 23.09.2026: 01.01.2026)
UPDATE appsmith.users
SET created_at = '2026-01-01 00:00:00',
    updated_at = '2026-01-01 00:00:00';

-- 3. Функция
CREATE OR REPLACE FUNCTION appsmith.set_updated_at() RETURNS trigger AS $$
BEGIN
    NEW.updated_at := now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- 4. Триггер (после бэкфилла)
CREATE TRIGGER trg_users_updated_at
    BEFORE UPDATE ON appsmith.users
    FOR EACH ROW
    EXECUTE FUNCTION appsmith.set_updated_at();
```

### Корректировка 23.09.2026 (вечер): updated_at = NULL до первого изменения

```sql
-- Убрать DEFAULT now() и NOT NULL: при INSERT updated_at = NULL
ALTER TABLE appsmith.users ALTER COLUMN updated_at DROP DEFAULT;
ALTER TABLE appsmith.users ALTER COLUMN updated_at DROP NOT NULL;

-- Обнулить существующие (триггер временно отключён, иначе он заполнит now())
ALTER TABLE appsmith.users DISABLE TRIGGER trg_users_updated_at;
UPDATE appsmith.users SET updated_at = NULL WHERE updated_at IS NOT NULL;
ALTER TABLE appsmith.users ENABLE TRIGGER trg_users_updated_at;
```

Выполнено 23.09.2026: снапшоты `Appsmith_DB` `8b00d7e` (до) / `ddde1d3` (после).

### Корректировка 23.09.2026 (день): время везде в МСК явно

Правило проекта (решение пользователя 23.09.2026): все timestamp-значения хранятся в **московском времени** явно — `(now() AT TIME ZONE 'Europe/Moscow')` вместо `now()` (причина: JDBC-соединение Appsmith работает в GMT и игнорирует server timezone; проверено фактом). Применено: DEFAULT `created_at`, функция `set_updated_at()`, SQL-тела 9 запросов приложения (запись и сравнения). Существующие GMT-значения пересчитаны +3 ч. Снапшоты: `d2cf892` (до) / `817a990` (после). Полный скрипт — `db-migration.sql` (блок «Корректировка … день»).

Примечания:
- Скрипт идемпотентным НЕ делаем (структурная миграция — применяется один раз; повторное выполнение контролируется снапшотами и ревью).
- Все выражения в одной транзакции (`BEGIN; … COMMIT;`) — атомарность миграции.
- После миграции — обязательный снапшот `Appsmith_DB` «после» и актуализация Grammax 51 / [[Схема БД]].
- **Итоговая фактическая схема (23.09.2026):** `created_at` NOT NULL DEFAULT (now() AT TIME ZONE 'Europe/Moscow'); `updated_at` без DEFAULT, nullable — NULL до первого UPDATE, далее заполняется только триггером (МСК).
